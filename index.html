02Work

ReconX: Transaction Reconciliation Dashboard

Upload two CSVs, find every mismatch, and get a plain-English summary of what likely went wrong.

  1. 01 Upload

    Two CSVs: an internal ledger and a counterparty statement.

  2. 02 Match

    Hash-map lookup by transaction ID.

  3. 03 Classify

    Matched, amount mismatch, or missing on either side.

  4. 04 Explain

    One Gemini call turns the counts and up to five sample mismatches into a short summary.

The problem

Matching an internal ledger against a counterparty statement by hand is slow and error-prone.

What it does

  • Matches CSVs of up to 10,000 rows each by transaction ID using hash-map lookups (a JavaScript Map: constant-time lookup per record).
  • Classifies every record as matched, amount mismatch, or missing on either side.
  • Auto-detects common column headers (txn_id, narration, value_date).
  • Results table with filters, search and CSV export.
  • One Gemini API call returns a short summary of likely causes and next steps, built from aggregate counts and up to five sample mismatches. The 200-word limit is a prompt instruction, not enforced.
D1

Code decides, the model explains.Matching is deterministic. The model never does arithmetic and never sees the full dataset.

D2

Stateless API, no database.The browser parses the CSVs and sends the rows to the API. The server matches them per request and keeps no database or files.

D3

The key stays on the server.The Gemini API key is used only on the server and never reaches the browser.

Known limits, also listed in the README

  • Amounts are floats compared with a 0.01 tolerance. Integer paise or Decimal would be correct for money.
  • Duplicate transaction IDs are not detected: the last row with a given ID wins.
  • Dates are displayed, not matched on, so timing differences are not handled.
  • No automated tests, and no rate limiting on the API.
